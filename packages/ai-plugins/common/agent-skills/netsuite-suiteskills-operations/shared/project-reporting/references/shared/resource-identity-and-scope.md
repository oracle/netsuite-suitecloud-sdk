# Domain reference

Support the user’s requested analysis and authorized actions through available, supported tools. Establish the target, intended effect and required business inputs before acting; reuse authorization already given for that exact scope. Tool availability and source examples do not grant authorization. Preserve business validation, actual host approvals and account permissions. If the operation or required procedure is unavailable, explain the specific gap and provide a useful proposal without claiming execution.

# Resource identity and authorized scope
Coordinated runtime: PM-4.0.0. Distribution release: PM-2026-09-24_v8. Capacity/native component behavior and stamps remain PM-3.0.0.

For unqualified all-project/portfolio scope, enumerate the complete visible authorized population. Do not sample, select only warning projects, or stop at the first project. For explicit IDs or filters, preserve that scope. Resolve account-specific lifecycle meanings and report activity/status inconsistencies separately.

Enumerate the authorized Project Resource population independently of planned-work rows. Preserve employees, vendor/contractor resources, named resources with zero recorded planned work, generic placeholders, inactive resources, and eligibility-unknown resources. Do not lose them through an inner join to work or time.

The complete resource population supports risk and capacity investigation. It is distinct from the narrower default placement candidate population in `placement.md`.

For “my” or equivalent personal scope, obtain the authenticated entity type and exact reference, then resolve its exact employee/vendor Project Resource mapping using verified identifiers and joins. Do not match by approximate name, email, project-manager label, or security-role title. If no reliable session identity or mapping is exposed, record the personal-scope limitation and continue independent portfolio work.

Keep security permissions, Project Resource role, and task/approval ownership separate. Inspect actual permitted data; do not select Administrator by default or switch roles automatically.

For a resource’s capacity, include all authorized overlapping `plannedwork` commitments within the evaluated window, including other projects affecting that resource. Respect disclosure scope. Hidden competing commitments limit confirmed availability; do not infer that they do not exist.
