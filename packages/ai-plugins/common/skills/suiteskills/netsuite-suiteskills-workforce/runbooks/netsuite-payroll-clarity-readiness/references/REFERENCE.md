# Confirmed sources and capability gates

Read this before discovery. Read [dashboard.md](dashboard.md) when producing the assessment dashboard.

## Evidence boundaries

The record/field mappings below were confirmed by NetSuite connector metadata on **2026-10-13** in the development account. They are schema evidence, not data-read results, feature-state evidence, or universal availability guarantees. Refresh metadata for the connected account/role before use. Preserve exact names returned by that metadata; REST record/sublist schemas and SuiteQL schemas are not interchangeable.

Use current callable SuiteQL metadata before dependent queries; record metadata does not establish query fields or joins. Use record metadata where needed to resolve uncertain record/sublist fields. A REST-only metadata failure does not deny independently supported SuiteQL; a denial of the underlying data remains binding. Stop dependent queries if essential schema is unavailable. Match the host's exposed tool names; do not assume their provider prefixes. For employee and transaction queries, start with `pageSize: 1000`, `pageIndex: 0`, stable ordering, and retrieve the remaining pages using returned pagination metadata. Check sublist `count`, `totalResults`, and `hasMore` separately. If a tool cannot retrieve remaining sublist pages, disclose partial coverage rather than treating absent lines as missing setup.

Maintain a small evidence ledger per run: **Check | Gate/applicability | Record and fields | Read operation and scope | Coverage | Result/reason**. Store tool response references and snapshot time with the evidence; do not embed payroll amounts or employee data into this reusable skill.

## Gate outcomes and fallback

The gate is about **native NetSuite Payroll**, not whether the company pays employees through another system. `PAYCHECKJOURNAL` and `PAYROLLSERVICE` have separate documented IDs. Do not equate them with `PAYROLL` or expand this workflow to those products without the user's choice.

- **Enabled:** proceed, then discover access and applicability per source/check. Permission failures affect coverage, not feature state.
- **Disabled:** skip native next-period discovery and checks with `reviewed: not-applicable`, outcome `Not applicable — PAYROLL disabled`. Retain readable employee observations; do not flag employee workplace/tax/bank/earnings gaps against native payroll requirements. Report readiness not assessed.
- **Unknown:** ask once for the checkbox state, record the inability to read it, and group dependent checks with `reviewed: unverified`, outcome `PAYROLL state unknown`. User confirmation must remain labelled user evidence. Accessible employee observations can still be completed.

No feature-enable, record-update, calculation, approval, or payment operation is authorized by this skill.
