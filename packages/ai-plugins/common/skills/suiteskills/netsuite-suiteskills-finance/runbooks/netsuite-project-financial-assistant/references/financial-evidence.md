# Financial Evidence Mapping

Resolve requested project identities and compatible scope before retrieval. Use actual supported connector schemas and the pinned retrieval/financial verification contracts. No hardcoded report ID, guessed SuiteQL or alternate interface after a data denial is authorized by this procedure.

| Stage | Branch to establish | Map only after verification | Missing evidence behavior |
| --- | --- | --- | --- |
| Project directory | Supported selected-project read, matching directory search/report or current-metadata query | Stable project/customer relationships and requested filters; active status only from established meaning | Requested unresolved projects remain disclosed; do not infer scope from profitability rows |
| Profitability | Verified project-detail financial report/search, or reconciled authoritative transaction source with project relationships | `projects` rows, source revenue basis, observed cost, compatible currency/book/period and provenance | Customer summaries are not project financials; report unavailable/partial project coverage |
| Unbilled | Supported source whose unbilled measure and project/customer grain match the request | Signed observations; actual source references; compatible scope; complete atomic membership when aggregating | Preserve separate observations, subtotal unavailable when membership cannot be established |
| Aging | Supported scoped aging report/search with actual cutoff and population definition | `aging.asOf`, customer/project grain, overdue amount, currency and source coverage | Current or partial rows cannot establish a complete historical or no-overdue claim |

The pinned shared binding candidates can guide discovery of report names and possible record fields. They do not establish availability, project grain, recognized revenue, accounting book or report parameter support. A label that also resolves to a project does not prove that a customer-level amount belongs to that project. Unresolved grain remains unknown, not automatically customer or project.

Record actual source identity, supported parameters, date/cutoff, scope, pagination/caps and source time. Verify search filters and report meanings; successful execution and exhausted pages establish only the actual declared population. Do not infer missing posting-period assignments from transaction dates. Use independent financial controls on matching grain/basis where required; do not manufacture a control from the calculated result.

Use known supported evidence directly when appropriate. Absence of report listing alone does not block an independently verified matching search/record/query branch. Missing query metadata blocks the dependent query. A fallback must be separately supported and semantically equivalent; it may not evade access denial or silently widen scope.

Partition compatible currency/book/period groups and map only qualified evidence into the financial input contract. Missing cost is null; zero cost is an observation only when actually returned. Never infer work in progress from an unbilled label, revenue recognition from a report name, or budget variance from revenue minus cost. Source population/permission limitations remain visible in each stage.
