# Domain reference

Support the user’s requested analysis and authorized actions through available, supported tools. Establish the target, intended effect and required business inputs before acting; reuse authorization already given for that exact scope. Tool availability and source examples do not grant authorization. Preserve business validation, actual host approvals and account permissions. If the operation or required procedure is unavailable, explain the specific gap and provide a useful proposal without claiming execution.

# Capability and source selection
Apply the bundled connector baseline with integration clarifications. Discover real tool descriptions/schemas before invocation.
For ordinary facts prefer compatible standard Reports → Saved Searches → metadata-backed Records → authorized metadata-backed read-only SuiteQL.
Compatibility requires definition, project/resource attribution, grain, full window, currency/book, permissions, and complete population.
Do not dispatch a report for every project when its tool returns only summary columns and exposes no project filter: a project-titled report is not project-level evidence.
Discover required report parameter flags, valid subsidiaries/books/contexts, and retain missing flags as unknown.
For native risks first resolve an available Indicator transport under project-indicators.md. Read all types/statuses, not only warnings.
Keep statuses: not_probed/listed/schema_verified/read_verified/denied/tool_missing/feature_absent_confirmed/incompatible/unknown.
A descriptor is not a successful metadata query, permission grant, feature-presence proof or complete data read.
Do not infer permissions by role name. Cache permanent missing-capability results within the same fingerprint rather than retrying per project.
Use verified join paths; do not use dated field catalogues or source SQL as executable contracts.
Preserve nulls and unknown counts; do not automatically NVL missing evidence to zero.
Apply posting/approval filters to the specific fact; timebill's supplied Approved=3 differs from baseline's generic transaction approval example.
Pagination: follow actual capability parameters, bounded pages, stable ordering, de-duplication and total reconciliation.
The baseline's <=1000 query-page rule is not a cap on the total answer. Never cap aggregate input before GROUP BY or page the same first 1000 rows.
If paging plus query bounds cannot be reconciled with the exposed tool, choose another complete channel or record incomplete retrieval.
No query, message or write is dispatched by the bundled offline helpers. No Business Metrics or stored-risk providers are added.
