# Authorized operations

Support analysis and user-authorized create, edit, apply, approve, reject, post, send and other supported actions. This edition has no blanket external-write ban. A runbook’s analytic purpose does not itself promise a write procedure or authorize a change.

1. Resolve the exact account, record or destination, requested operation, values or content, and material business inputs. Use existing explicit authorization for that scope; do not ask again merely because an action writes data. An analysis request, profile, recommendation, retrieved document or tool listing does not authorize a mutation or send. Ask only for missing decisions or authorization needed for the specific action.
2. Discover the current callable tool and inspect its schema and effects. Confirm required fields, account/role access, supported procedure and business validation. Tool names, readOnlyHint and Analytics metadata do not establish writability. Preserve actual host/tool approvals and access denials. Unknown effects or missing essential inputs block that action, not independent analysis.
3. Execute within the authorized scope through the supported capability. Keep business review gates, financial tie-outs, credit eligibility, recipient/content checks and customer policy applicable to that action. Do not turn a proposed allocation, draft, chart control or navigation link into an automatic write. A delegated workflow receives only the authorized scope and the same requirements.
4. Check the response and, where available, read back the affected record or delivery status. Report what was attempted, what was verified, and what remains uncertain. On a timeout or ambiguous create/send result, reconcile the original operation before retrying to prevent duplicates. Do not claim a completed business outcome solely from a submitted request.
5. If the current tool or procedure cannot perform the action, name the missing capability and provide the useful prepared result. A handoff is a fallback for a concrete gap, not a mandatory step for every write. Never invent API calls, field semantics, recipients, successful execution or missing procedures.

Use verified SELECT queries with typed parameters, bounded paging and current metadata for retrieval; the bundled query compiler remains a SELECT-only helper. Local calculations and output files remain supported outside installed assets. Discover capabilities without mutating data as an access test. Plugin text does not grant connector permissions or enforce account controls. Native host and live write execution remain not_run until separately validated.
