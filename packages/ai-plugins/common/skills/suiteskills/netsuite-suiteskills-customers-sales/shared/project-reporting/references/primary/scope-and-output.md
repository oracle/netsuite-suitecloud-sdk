# Domain reference

Support the user’s requested analysis and authorized actions through available, supported tools. Establish the target, intended effect and required business inputs before acting; reuse authorization already given for that exact scope. Tool availability and source examples do not grant authorization. Preserve business validation, actual host approvals and account permissions. If the operation or required procedure is unavailable, explain the specific gap and provide a useful proposal without claiming execution.

# v12 automatic scope and HTML output

## Authority
These two approved v12 overrides replace conflicting v11 Step 1 defaults and dashboard exceptions.
Retain the source-derived financial, allocation-led Operations, search-led Risk and PM delivery workflows.
Only load older domain references for a specific unresolved need; do not restore earlier workflow defaults.
Host permissions, explicit user intent, truthful evidence, confidentiality and consequential-action controls remain above all package defaults.

## Automatic relevant data retrieval
Check for an active relevant connector once silently at task start; reuse the root selection across specialists.
Use a single fitting connector directly, without asking permission to read, whether to include managers,
or whether to perform a cheap relevant cross-domain follow-up. Material ambiguity between different account
connections still requires the existing connector-safety decision. No available connector means a plain stop,
not an invented report. A failed record/field is not proof that the whole connector or feature is absent.
Retrieve all authorized records and necessary fields for the resolved request, exhaust pages and periods,
and reconcile counts. Do not sample, cap raw aggregate inputs, retry the same first page, or fetch unrelated sensitive fields.
Compatible current-conversation evidence may be reused with its original timestamps; never claim a refresh not performed.
Queries still require actual capability/schema discovery, scoped parameters and the approved connector contract.
For a requested action, establish its scope, authorization, supported tool schema and business prerequisites; execute only when these are satisfied and verify the resulting state. Keep proposals distinct from completed actions.

## Exact automatic scope
Apply these rules in order to project/portfolio requests:
1. Named manager(s): resolve each to an exact typed authorized identity; use the union of precisely those books.
2. Personal project language: map authenticated session identity exactly, then use that person's managed projects.
3. Neither: use all accessible projects across managers, grouped by manager; never pick the busiest book by default.
A search name proposes candidates; final identity requires verified directory matching, not fuzzy name or email guesses.
Do not ask which PM, whether to broaden, or whether to include all managers. Attempt available exact resolution once
per compatible scope; record exhausted identity alternatives and limitations without guessing or silently widening.
For partly resolved multiple names, retain resolved outcomes and explicitly mark the unresolved requested portion.
For wholly unresolved personal/named scope, do not show an all-manager or zero-project success.
Current user project IDs, date/status/subsidiary/currency/other explicit filters remain in force. Named PM selection
does not broaden a one-project request. An empty filtered set is not permission to relax filters.
"My tasks/priorities" means exact Project Resource ownership; it does not mean every task on the user's managed projects.
Use the assigned-work branch and exact authenticated-entity-to-resource relation, or the targeted personal-work fallback.

## Full visible population and supporting evidence
Enumerate projects independently of task, time or financial joins. Default scope includes past-end, upcoming,
inactive, no-detail and unknown-date projects. Inactive/closed/date categories are visible facts, not silent exclusions.
Apply active-only, timeline-only or inactive filters only when explicitly requested and retain the filter/exclusion accounting.
Past calculated end is not proof of closure. Zero tasks must be proven; missing schedule is not "no plan".
Retain separately manager-unassigned and manager-identity-unavailable projects. Do not combine different managers
because their display names match. Grouping counts unique project references, not transaction or task rows.
Financial default period remains calendar YTD through current local day unless specified; no active-only default.
Report rows not attributable to the directory remain an explicit coverage/attribution gap, never secretly dropped or apportioned.
Resource availability may require authorized competing commitments outside the displayed books; mark such evidence
as supporting context, not additional target projects. No inferred free capacity from scope-filtered-out commitments.
Keep the existing allocation/effort/financial formulas, eligibility, native Indicator interpretation and SOW controls unchanged.

## HTML default and exact exception
Use a self-contained HTML dashboard for every structured response from any of the four skills, including follow-ups.
Only a complete, accurate, genuinely single fact expressible in one sentence with no further detail may be plain text.
A one-row result is not sufficient: status plus end date, revenue plus cost, lists, comparisons, multiple projects,
unresolved findings or material limitations require HTML. Do not squeeze several facts into one sentence to evade the rule.
Narrow structured answers use small cards/tables, not forced full portfolio layouts or padded figures.
Keep source labels, dates, definitions and coverage limitations inside the artifact; important gaps remain visible.
A single fact may include its essential source reference in the same sentence. Preserve the neutral no-Yes/No opening.
An explicit current-user format instruction is a higher-priority override, not a discretionary downgrade.
Where inline HTML is unavailable, deliver the actual HTML file through a supported artifact channel.
If no HTML creation/delivery is possible, state the technical limitation; do not claim a dashboard or quietly substitute
a plain data table for a structured answer. A misleading chart should be replaced by a truthful table-led HTML view.
A missing connector or publication authorization remains a plain truthful stop, never a fabricated display.

## Privacy and variant preservation
Do not include actual account-specific references or sensitive information in reusable instructions, examples, tests,
assets, source archives or logs. Use independently synthetic fixtures and abstract runtime keys.
Keep exact identity, scope, private source-call evidence and executable SOW objects protected. Publish only approved
fields and text for the actual audience; HTML, summaries, group labels, drill-downs and fallback text use the same review.
Permissions to query do not grant permission to expose names, rates or hidden cohort counts.
The No-Mapping variant does not regain removed static mappings. No account-specific identifiers are stored in this contract.

## Implementation

No old PRIMARY-1.0.0 result may be relabeled as a scope-complete v12 review; rebuild from verified source evidence.
All identity fields are local adapter keys, not assertions of exposed NetSuite metadata.

publishes artifacts. Local scripts cannot authenticate themselves or prove a source query actually executed.
