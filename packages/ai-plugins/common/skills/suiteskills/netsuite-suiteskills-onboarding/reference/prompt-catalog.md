# Starter prompts

Use these analytical examples only when the actual available workflow supports the requested outcome. Render a goal plan after the two answers, accepted existing answers or an explicit fallback selection. Select by actual description and procedure; the names below do not register services or prove availability. User selections are actual chat submissions or a supported host submission event, never assumed from a rendered button.

| Goal | Illustrative starting prompt | Candidate workflow |
|---|---|---|
| Close | Show the observed status of [period] and the unresolved steps evidenced for [scope]. | Period Close Status |
| Variance | Explain the largest movements for [scope], [period] against [comparison], with currency and coverage. | Variance and Flux Analysis |
| Financial review | Review the financial statements for [period/scope] and distinguish evidence from questions to investigate. | Financial Statement Review |
| Cash | Summarize cash and liquidity for [scope/as-of date], retaining currency and evidence gaps. | Cash and Liquidity |
| Collections | Prioritize overdue invoices within [scope/as-of date]; prepare recommendations. | Invoice Collections |
| Payables | Review bills due in the next 14 days within [scope/as-of date]; do not execute payments. | Payment Prioritization |
| Spend | Explain vendor spend changes between [comparison periods] within [scope]. | Vendor Spend Analysis |
| Fulfillment | Review late orders in [scope] and explain the supported fulfillment evidence. | Fulfillment performance insights |
| Stock | Check availability for [item/location] using the workflow's supported definitions. | Inventory Availability Lookup |
| Customer | Trace the supported status and linked transactions for [sales order]. | Customer Service Order Triage |
| Executive | Summarize [period/scope] results and the supported issues needing attention. | Executive financial reporting |
| Administration | Show what access-review workflows are available, and distinguish missing capabilities from access denials. | Current exposed specialist or capability discovery; no fabricated user-audit route |

Use one primary recommendation, then relevant supporting workflows with up to three prompts each. Do not promise exhaustive coverage from partial discovery. A missing dependency is disclosed. Do not add specialized workflows merely for breadth, or claim a visualization prerequisite is satisfied by a similar name.

Placeholder values are user inputs, not verified account facts. Preserve explicit user scope and ask only for material missing inputs. Never preload real personal/entity names without an established appropriate scope. A copied prompt or opened composer is only preparation; the user sends/selects it. No custom message-sending API is supplied. Adjust asks for the goal again. “Show everything” lists available workflows by area in a separate chat turn. No separate page or browser launcher is introduced.

These starters request analysis. If the user separately asks for a supported action, apply its domain procedure and the shared action contract, reusing exact authorization. A displayed plan never authorizes the action. Do not use an automatic alternate workflow on denial, empty results or error.
