# Domain reference

Support the user’s requested analysis and authorized actions through available, supported tools. Establish the target, intended effect and required business inputs before acting; reuse authorization already given for that exact scope. Tool availability and source examples do not grant authorization. Preserve business validation, actual host approvals and account permissions. If the operation or required procedure is unavailable, explain the specific gap and provide a useful proposal without claiming execution.

## Narrative portfolio review
Default for suitable broad project/portfolio findings, not every answer.
Header: neutral findings statement, title, exact permitted population and as-of/timezone.
Distinguish retrieval from evaluation and business cutoff. Say "live" only if a real
retrieval occurred and explain asynchronous source freshness. Source-only plans and
synthetic examples must have accurate labels.

Overview: choose relevant KPI cards (often 3–5, but fewer/none allowed), a useful
comparison, and coverage banner. Numeric colors require a supported severity
classification; neutral counts remain neutral. Denominator, unit, definition and
source accompany each measure.

Insights: one card per synthesized finding. Show Confirmed evidence and an optional
explicit Interpretation, with sources and limitations. Do not force speculation.
Co-occurrence means exact verified entity joins across independently supported
conditions. Do not infer higher severity, causality, a critical path, or an account-wide
pattern from two flags. Concentration uses distinct affected projects and a reconciled
denominator; "disproportionate" requires a separately supported reference population.
Do not attribute all project risks to every resource.

Sourcing: retain ordered requested answers, all applicable risk evaluations, source
pages/periods and alternatives, extra detail and proposed-action state. Repeat material
gaps near the overview, not only behind a tab. Show the exact permitted resource and
failure reason; protect raw SQL, private search names, credentials and diagnostics
when the audience is not authorized. Distinguish denied, missing tool, incompatible
definition and confirmed feature absence; route remediation to the appropriate owner.

Place a dated source caption beneath every chart and next to the relevant narrative.
Source types include native results, reports, records, searches, queries and documented
calculations. The footer describes actual lineage, not "every number was queried today"
or "no estimated numbers." Recorded estimates are legitimate when labeled.

## Project-manager portfolio
This is a preset inside Portfolio Health, not a fifth skill. Operations supplies tasks,
schedule and time facts; Financial validates commercial/actual measures; Risk performs
the complete applicable native-first review. Exact PM resolution and full authorized
project scope remain upstream prerequisites.

Prefer manager context, relevant cards, project financial selection, attention findings,
status controls, a recorded-date timeline and complete project table. Components may be
reordered or shown as tables when data/host constraints warrant.
A picker changes only the local financial-detail view. Status chips/sorting affect the
project-detail table; root totals, chart definitions and evidence gates do not change.
Every requested question remains represented even when components are reorganized.

Financial comparison: committed revenue, actual recognized revenue and supported actual
cost are distinct measures. Contract value is separately sourced, never renamed to
committed revenue automatically. Labor cost is never billing rate; labor-only cost must
be labeled and not presented as total project cost. Keep currencies, books, periods,
tax/cost inclusions and definitions compatible; otherwise withhold that comparison.
Use the existing task-metrics helper for effective due dates and overdue executable
leaf tasks. Do not hard-code a guessed duedate/status filter or sum task parent rollups.
Directory "not inactive" is not the same as Active lifecycle; no-plan is a separate
documented state, and missing data is not proof of no plan.

Numerical differences are displayed as calculated variances, not the only risk logic.
Preserve native observations, supported qualitative risks and data gaps alongside them.
No "meaningful" percentage threshold without a recorded/user-specified rule.
Zero contract value with cost/time does not prove a loss or an unentered sale;
report the observation and unresolved cause. Unknown/withheld remains distinct from zero.
Timeline bars use verified date semantics, not whichever task date is available.
Retain unfinished past-end projects; layout exclusions must not alter root populations.

## Dashboard-first broad reviews (inherited, coordinated in v8)
Use [review-depth.md](review-depth.md) as the controlling evidence/delivery workflow.
Broad reviews, comparisons and multi-item analysis across delivery, operations,
financials or risk normally produce rendered HTML/artifacts, not an unannounced
Markdown-only dump. Prefer real host inline tools; otherwise deliver portable HTML.
Use 3–5 relevant summary cards and 1–2 suitable overview charts, followed by sourced
Confirmed evidence, optional labeled Interpretation and a visible coverage-gap callout.
Card/chart counts are evidence-backed targets, not permission to fabricate a measure.
Keep full permitted detail, original requested order, source captions and definitions.
Partial data do not imply no dashboard: render an explicitly Limited/Incomplete review
when truthful. Fallback must name unsupported delivery, misleading visual encoding,
or explicit user text preference; it preserves all permitted detail. Failed publication
authorization blocks every format. A genuinely simple named-item fact may remain concise; a multidimensional finding still uses a graphical dashboard.
The numerical/causal/risk and SOW action boundaries are unchanged.

Runtime assets are component CSS/JavaScript, not saved data or page templates.
The registries and privacy field allowlists are in
[visual-config/recipes.json](visual-config/recipes.json),
[visual-config/layout-presets.json](visual-config/layout-presets.json) and
[visual-config/presentation-fields.json](visual-config/presentation-fields.json).
Development artifacts are generated outside the installed skill and never used as
literal findings. Changing layout cannot change scope, numbers, privacy or approvals.
