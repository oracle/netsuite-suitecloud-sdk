# Closed specification contract

`schema_version: 1`, title, question, domain, export_name, source, columns, rows, charts and references are the only root fields. The adjacent JSON Schema records structural requirements; contract.py implements cross-field, grain, currency, binding and measure-unit checks. JSON duplicate/prototype keys and nonfinite numbers are rejected. Maximum input is 16 MiB.

Every source carries kind (supplied/netsuite), label, UTC retrieved_at, scope, filters, status (preliminary/final/limited), completeness (complete/partial/unknown), expected_rows, grain and limitations. Denied/failed results cannot become rows. Complete means expected_rows equals supplied rows; this verifies assertion consistency, not account pagination itself. Partial/unknown requires limited and at least one limitation. The producer must substantiate completeness externally.

Each column has a unique lowercase key, literal label and type text/date/number. Numbers require kind, unit and currency. Money uses `kind: money`, an explicit three-uppercase-letter currency code and the same unscaled code as unit (for example `unit: USD, currency: USD`). The producer must substantiate currency identity; syntax validation is not an ISO registry or source attestation. Other kinds require null currency. Nonmoney units are closed: number=dimensionless; count=records/orders/items/units/events/people/cases/transactions; quantity=each/units/kg/g/lb/oz/l/ml/m/cm/mm/hours/days/minutes/seconds/boxes/cases/pallets/board_feet; ratio=ratio/percent. Unsupported measures require a reviewed contract extension. Financial labels and domain are accepted without another plugin. Missing values are refused rather than silently plotted. See `examples/supplied-revenue.json` for synthetic supplied money and prior-year series.

Each row has exactly the declared keys. Grain values uniquely identify rows. Charts use type/title/x/y plus only the type-specific fields in [chart-contract.md](chart-contract.md). The executable chart validator enforces axis types, measure compatibility, complete supplied shares, supplied intervals, positive sizes and bounded explicit series. Dates and unlike units stay distinct. Every mark maps to one row and explicit measure; no source rows are combined locally. Source aggregate rows require a verified producer basis/grain. Local rendering does not prove business definitions.

No aggregation, formulas, percentages, conversions, custom colors, remote fonts, rich text or executable customization is accepted. Business strings including markup and URLs remain literal. null/zero/missing distinctions are preserved by refusing missing measures while accepting real zero.
