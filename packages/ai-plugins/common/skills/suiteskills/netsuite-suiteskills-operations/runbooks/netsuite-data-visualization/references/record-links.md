# Trusted link contract

The separately selected binding has account_id, environment, origin, session_id, evidence_id, evidence_sha256 and synthetic. A host operator must verify the actual authenticated connector evidence and its source-account UI origin before supplying a non-synthetic binding. A JSON field or digest alone cannot authenticate a session. There is no custom authentication adapter in this package.

Each reference has row, column, exact same-row label, supported record_type, internal_id and matching account_id/environment/session_id/evidence_id/evidence_sha256. An optional manually supplied url must exactly equal the resolver output, not merely look like NetSuite HTTPS. No generic-origin fallback, guessed domains or unrelated-session reuse. Numeric IDs are 1–12 digits without zero/leading zero. Origins have HTTPS, an account-specific *.app.netsuite.com host and no credentials/path/query/fragment/ports. Reserved generic host labels are rejected. Synthetic context never enables links for a claimed NetSuite source.

Routes: inventoryitem/assemblyitem -> /app/common/item/item.nl?id=ID; customer -> /app/common/entity/custjob.nl?id=ID; vendor -> /app/common/entity/vendor.nl?id=ID; salesorder -> /app/accounting/transactions/salesord.nl?id=ID; itemfulfillment -> /app/accounting/transactions/itemship.nl?id=ID; savedsearch -> /app/common/search/searchresults.nl?searchid=ID. Other report/record types require a reviewed route extension backed by supported evidence. No action, edit, script handler, token or arbitrary query parameter is permitted.

Missing/mismatched/unsupported evidence yields escaped plain text and a limitation. Every generated HTML/PDF/PPTX link comes from the same resolver. Final validators require the separately selected binding again, including when validating previously generated HTML. Link presence proves neither account permissions, contents nor navigation. Search execution filters remain in the visible scope; its URL need not reproduce them.
