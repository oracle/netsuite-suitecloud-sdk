# Domain reference

Support the user’s requested analysis and authorized actions through available, supported tools. Establish the target, intended effect and required business inputs before acting; reuse authorization already given for that exact scope. Tool availability and source examples do not grant authorization. Preserve business validation, actual host approvals and account permissions. If the operation or required procedure is unavailable, explain the specific gap and provide a useful proposal without claiming execution.


# Resource coverage investigation — sanitized technical lessons
V5-SANITIZED-1. Historical project/personnel results and replacement recommendations
are not distributed. No account population or observed result count is supplied.

## Native-first investigation
Read the available native Project Indicator state before derived risk analysis.
Resolve the remaining-work coverage type through current metadata or an approved
account-bound mapping. Do not assume a literal type ID. Keep all returned statuses,
new types, missing pairs, freshness, permissions and historical-cutoff limitations.

Flat SuiteQL fields and structured/UI representations are distinct transports.
Validate `projectindicator`, project joins, type/status/severity labels and optional
level enrichments in the exposed channel. Never translate native Red into calculated High.

## Supporting coverage dataset
The candidate `projecttasktimeremainingrisk` source may expose `project`, `projecttask`,
`projecttaskassignment`, `missinghours`, `availablehours`, `remaininghours`, `blockedhours`,
`timeoffhours`, `scoringstartdate`, `scoringenddate`. Validate before querying.
Retain actual dataset row IDs and assignment/window keys internally for deduplication.
The filtered positive-gap view is not a complete task or resource directory.

Use `missinghours`, not total task work, to quantify a supported gap. A task showing
multiple current assignees does not establish which assignee owns each shortfall.
Never copy a task-wide gap to every assignee. Check calendar/leave definitions before
subtracting capacity reductions twice.

## Generic synthetic example
This example was independently constructed; it is not a renamed historical result.
For fictional task `SYNTH-TASK-ALPHA`, assignment `SYNTH-ASSIGNMENT-ONE` has
12 remaining hours and 7 compatible available hours in the same window; its confirmed
missing-hour field is 5. A second assignee on the task does not inherit that 5-hour gap.
The ratio can be calculated only when grain and definitions are validated. It does
not establish any native status without an actual returned native result.

## Broader staffing review and change control
Independently sweep unassigned work, generic/inactive/ineligible resources and unknown
capacity. Query authorized competing commitments when required. Empty allocation or
planned-time results alone do not prove availability. Ordinary candidate capacity
uses dated `plannedwork`, calendars and leave; default candidates are employees in the
same recorded role. Price ranking requires an explicit request.
No stored custom risk register or Business Metrics provider is assumed.
After an authorized operational change, read back the source and separately observe
an actual native reevaluation; do not promise a refresh or infer its color.
